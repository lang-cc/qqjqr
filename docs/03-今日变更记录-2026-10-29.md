## 二、429 限流：加排队代理

**现象**：日志刷 `429 Non-streaming text concurrency limit exceeded`，回复经常直接失败。

**原因**：网关限制"非流式文本并发 = 2"，而 AstrBot 一次回复会并发多个请求（分段 + 记忆 + 表情包）。

**做法**：`tools/gw_proxy.py`

| 项 | 值 |
|---|---|
| 监听 | `127.0.0.1:8878` |
| 限流 | `asyncio.Semaphore(2)` 队列 |
| 统计 | `req / queued / err / cancel` |
| 健康检查 | `GET /health` |

模型 `base_url` 从网关直连改成 `http://127.0.0.1:8878/v1`。

**踩坑与修正**：

| 坑 | 修正 |
|---|---|
| `err` 一直在涨，其实是 AstrBot 主动取消流 | `ClientConnectionResetError / CancelledError` 单独计为 `cancel`，不算错误 |
| 早期只读日志尾部 400KB，历史 429 统计成 0 | 改成**增量按字节偏移扫描**，断点存 `data/logs/console_stats.json` |
| 日志里 `429` 出现在无关文本（URL、续行）被误计 | 改成严格匹配 + 必须带时间戳 |

**验证**：`curl 127.0.0.1:8878/health` → `err=0`；当天 206 次 429 全部发生在代理上线（18:49）之前。

## 六、新增插件：`astrbot_plugin_xiaonian_interest`（兴趣接话 + 引用补丁）

**要解决的问题**：群里没 @ 它、没打唤醒前缀时，AstrBot 完全不看那条消息；@ 了又经常不回复。

**判定链**：

```
群消息 → 自己发的/太短/冷却中/超每小时上限 → 丢弃
        → 关键词粗筛（命中 或 15% 盲抽）
        → 模型打分 0~10（20 秒最多判一次，控成本）
        → ≥阈值(6) → 放行给正常回复链路（人设/记忆/TTS/表情包照旧）
        → <阈值 → 静默丢弃
```

**关键技术点**：只要注册了 handler，AstrBot 就会把"没被叫的消息"也标成唤醒状态，
所以不想回的情况**必须 `event.stop_event()`**；决定要回时把 `event.is_at_or_wake_command = True`，
后续 `star_request` 才会真的发 LLM 请求。

**默认参数**：

| 项 | 值 |
|---|---|
| 阈值 | 6/10 |
| 冷却 | 90 秒 |
| 每小时上限 | 30 条 |
| 打分限速 | 20 秒 |
| 盲抽 | 15% |
| 最短字数 | 6 |
| 生效群 | <你的群号> |

**指令**：`/兴趣`、`/兴趣 开|关`、`/兴趣 阈值 N`、`/兴趣 冷却 N`、`/兴趣 上限 N`、`/兴趣 话题 a,b`、`/兴趣 引用 开|关`、`/兴趣 私聊引用 开|关`、`/兴趣 测试 一句话`

**实测**：

```
22:08:56 接话 ✔ 分=8 词=['部署'] → Prepare to send 成功
22:13:07 跳过 分=2  "泛指式发言…低信息量灌水"
```

## 七、引用回复失效：定位 + 修复

**现象**：配置里 `reply_with_quote = true`，但发出的消息从不引用。

**原因**：AstrBot 内置逻辑（`result_decorate/stage.py:428`）：

```python
# at 回复 / 引用回复仅适用于纯文本或图文消息
can_decorate = all(isinstance(item, (Plain, Image)) for item in result.chain)
if can_decorate and self.reply_with_quote:
    result.chain.insert(0, Reply(id=event.message_obj.message_id))
```

机器人是**语音回复**，链里有 `Record` → `can_decorate=False` → 引用和 @ 一起被静默跳过。

**修复**：在插件里加 `on_decorating_result` 钩子，不看类型，群聊/私聊都补 `Reply`：

```python
@filter.on_decorating_result()
async def ensure_quote(self, event):
    if event.is_private_chat() and not self.cfg("quote_private"):
        return
    mid = getattr(event.message_obj, "message_id", None)
    if not mid or any(isinstance(c, Reply) for c in result.chain):
        return
    result.chain.insert(0, Reply(id=mid))
```

**验证**：

```
22:38:39 已补引用(私聊) id=1992351370 链=['Reply','Plain']
22:39:29 已补引用(群聊) id=-734066331 链=['Reply','Plain']
```

## 八、Computer Use 权限

| 时间 | 动作 |
|---|---|
| 22:45 | 面板里把 `computer_use_runtime` 切到 `local` |
| 22:54 | 按用户要求"全部打开"：member / admin 都设为 执行=开、联网=开、文件=host；`computer_use_require_admin=false` |

**Windows 上的硬规则**（源码 `computer_tools/util.py`）：

```python
requires_sandbox = allow_execution and (not allow_network or filesystem_scope != "host")
```

只要"能执行但不许联网"或"只能看工作区"，就要求 OS 级隔离；Windows 后端状态是 `unsupported` → **直接拒绝执行**。
所以想要 Windows 上真能跑命令，只能是「执行开 + 联网开 + 文件 host」。

**实测**（用 AstrBot 自己的 `get_local_permission_policy`）：

```
member   执行=True 联网=True 文件=host 需要隔离=False 禁用原因=None
admin    执行=True 联网=True 文件=host 需要隔离=False 禁用原因=None
```

改前配置备份：`backups/auto/cmd_config.20261029-225418.json`。

⚠️ 副作用：**群里任何人 @ 它都有同等权限**（member 档也开了 host+执行）。
