# AstrBot 云服务器（Linux）部署一条龙

> 适用：一台 **Linux 云服务器**（Ubuntu 22.04 / 24.04 或 Debian 12，2 核 2G 起），7×24 挂机。
> 全程约 **50~70 分钟**。
> 最后更新：2026-10-29（对应 AstrBot 4.29.3）
>
> 代码仓库：https://github.com/lang-cc/qqjqr
>
> **先记住一件事**：Windows 那套用的 **SnowLuma 是靠"注入桌面版 QQ"工作的，Linux 服务器上没有桌面 QQ，用不了**。
> 云上要改成 **NapCat（无头协议端，Docker 跑）**，剩下的 AstrBot 部分几乎一样。

---

## 0. 架构对比

```
【本机 Windows】QQNT(桌面) + SnowLuma 注入  →  反向WS  →  AstrBot
【云服务器 Linux】QQ 账号协议端 NapCat(容器)  →  反向WS  →  AstrBot  →  (systemd 守护)
```

| 组件 | Windows 本机 | 云服务器 |
|---|---|---|
| QQ 协议端 | SnowLuma（注入 QQNT） | **NapCat**（Docker，无头，扫码登录） |
| 进程守护 | 桌面控制台 / 计划任务 | **systemd** |
| 面板访问 | `127.0.0.1:6185` 本机浏览器 | SSH 隧道 或 nginx + 密码 |
| 语音 TTS | 本机调 DashScope | 一样，但**要装 ffmpeg** |
| 数据 | `D:\qqjqr\data\` | `/opt/astrbot/data/` |

### 端口规划

| 端口 | 用途 | 是否对公网开放 |
|---|---|---|
| 22 | SSH | ✅（建议改端口 + 密钥登录） |
| 6199 | AstrBot 反向 WS（NapCat 连进来） | ❌ 只监听 127.0.0.1 |
| 6185 | AstrBot 面板 | ❌ 只监听 127.0.0.1 |
| 6099 | NapCat WebUI | ❌ 只监听 127.0.0.1（用 SSH 隧道） |
| 3001 | NapCat WS 服务端（可选） | ❌ |
| 8090 | nginx（可选，反代面板） | 看你需要 |

### 准备清单

| 项目 | 说明 |
|---|---|
| 云服务器 | 2C2G 起，Ubuntu 22.04+，磁盘 20G+ |
| 域名（可选） | 想用 https 访问面板才需要 |
| QQ 小号 | 手机在身上，NapCat 首次扫码/验证要用 |
| LLM key | 官方或中转网关 |
| DashScope key（可选） | 发语音才要 |


### 现场必问清单（给别人的机器部署时，照着问，别自己猜）

| # | 要问什么 | 填到哪里 |
|---|---|---|
| 1 | 机器人用哪个 QQ 号登录 | NapCat 扫码登录 |
| 2 | 你自己的 QQ 号 | `admins_id`；白名单私聊写 `平台ID:FriendMessage:你的QQ` |
| 3 | 要在哪些群生效 | `id_whitelist` 里写裸群号；兴趣接话插件的 `groups` |
| 4 | 用哪个模型 / 网关 | 供应商的 `base_url`+`api_key`+模型名；网关域名填 `tools/gw.local.json` 或 `GW_UPSTREAM` |
| 5 | 要不要发语音 | 要 → TTS 的 api_key（DashScope），`dual_output=false` |
| 6 | 面板/WebUI 密码谁定 | 首次登录自己设，**SnowLuma WebUI 只存哈希，丢了只能重置** |

> 本仓库所有模板里的账号、群号、域名、密钥**都是空的**，就是留给现场填的。

## 1. 服务器初始化

SSH 登录后（`ssh root@你的IP`）：

```bash
# 1) 更新 + 基础工具
apt update && apt upgrade -y
apt install -y curl wget git unzip vim htop net-tools ufw ffmpeg python3 python3-venv python3-pip

# 2) 时区（日志时间才对得上）
timedatectl set-timezone Asia/Shanghai

# 3) 建议加 2G swap（2G 内存的机器跑 TTS/大上下文会用到）
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 4) 防火墙：只放 SSH
ufw allow 22/tcp
ufw --force enable
```

> 云厂商的**安全组**也要放行 22（如果用 nginx，再放行 80/443）。6099/6185/6199 **不要**对公网开。

```bash
apt install -y git
```

```bash

useradd -m -s /bin/bash astrbot
```

```bash
cd /opt/astrbot
```

## 3. 装协议端 NapCat（Docker）

> 镜像名与默认端口会随版本变化，以下以 2026-10 的用法为准，遇到不一致**以官方 README 为准**：
> <https://github.com/NapNeko/NapCatQQ>

```bash
# 装 Docker
curl -fsSL https://get.docker.com | bash
systemctl enable --now docker
```

建目录 + 启动容器：

```bash
mkdir -p /opt/napcat/config /opt/napcat/qq
```

`/opt/napcat/docker-compose.yml`：

```yaml
services:
  napcat:
    image: mlikiowa/napcat-docker:latest
    container_name: napcat
    restart: unless-stopped
    environment:
      - NAPCAT_UID=1000
      - NAPCAT_GID=1000
      - MODE=astrbot          # 有的版本支持这个预设，不支持就删掉
    ports:
      - "127.0.0.1:6099:6099"   # WebUI，只给本机
      - "127.0.0.1:3001:3001"   # WS 服务端（可选）
      - "127.0.0.1:3000:3000"   # HTTP 服务端（可选）
    volumes:
      - /opt/napcat/config:/app/napcat/config
      - /opt/napcat/qq:/app/.config/QQ
```

```bash
cd /opt/napcat && docker compose up -d && docker logs -f napcat
```

### 3.1 扫码登录

两种方式：

| 方式 | 做法 |
|---|---|
| 看日志里的二维码 | `docker logs napcat` 会打印二维码链接/图片路径，浏览器打开后手机 QQ 扫 |
| WebUI | SSH 隧道后打开 `http://127.0.0.1:6099`（见第 8 节），里面有登录二维码和 token |

> 首次登录可能要过滑块/设备锁，跟着 QQ 提示走。
> 登录态会存在 `/opt/napcat/qq`，**这个目录要备份**，不然重装就得重新扫码。

### 3.2 配 OneBot 反向 WS（关键）

在 NapCat WebUI → **网络配置** → 新建 **WebSocket 客户端（反向 WS）**：

| 项 | 值 |
|---|---|
| 名称 | `astrbot` |
| URL | `ws://127.0.0.1:6199/ws`（**AstrBot 在宿主机上，所以不能用容器内的 127.0.0.1** ⚠️ 见下） |
| 消息格式 | `array` |
| Token | 留空（和 AstrBot 一致） |

⚠️ **容器网络关键点**：NapCat 在容器里，`127.0.0.1` 指的是容器自己。要让容器连到宿主机上的 AstrBot，用下面任一种：

| 方案 | URL 写法 |
|---|---|
| AstrBot 监听 `0.0.0.0:6199`，容器用 host 网关 | `ws://172.17.0.1:6199/ws`（docker0 网关） |
| compose 里加 `network_mode: host`（最简单） | `ws://127.0.0.1:6199/ws` |
| 给容器加 `extra_hosts: ["host.docker.internal:host-gateway"]` | `ws://host.docker.internal:6199/ws` |

推荐 **`network_mode: host`**（Linux 上可用，最省事），此时 ports 段要删掉（host 模式不用映射）。

## 4. AstrBot 平台配置

有两种改法：面板点，或者直接改 `data/cmd_config.json`。

### 4.1 面板方式

SSH 隧道（第 8 节）→ <http://127.0.0.1:6185> → 平台 → 新增 → `aiocqhttp`：

| 项 | 值 |
|---|---|
| ID | `napcat-onebot` |
| 反向 WS Host | `0.0.0.0`（容器要连进来；用 host 网络时 `127.0.0.1` 也行） |
| 反向 WS 端口 | `6199` |
| Token | 留空 |

### 4.2 文件方式

`/opt/astrbot/data/cmd_config.json` 里 `platform` 数组：

```json
[
  {
    "id": "napcat-onebot",
    "type": "aiocqhttp",
    "enable": true,
    "ws_reverse_host": "0.0.0.0",
    "ws_reverse_port": 6199,
    "ws_reverse_token": ""
  },
  { "id": "webchat", "type": "webchat", "enable": true }
]
```

重启后日志应出现：

```
aiocqhttp(OneBot v11) 适配器已连接。
```

## 5. 模型 / 人格 / 白名单 / TTS

这四项和 Windows 版完全一样，只把路径记成 `/opt/astrbot/data/cmd_config.json`。
详细字段说明见同目录的《01-Windows本机部署一条龙.md》第 6 节，这里只列云上**不一样**的地方。

### 5.1 模型

- `base_url` 填网关的 `https://xxx/v1`
- 云服务器**能直连外网**就行；如果网关限制 IP 白名单，记得把服务器公网 IP 加进去

### 5.2 白名单（改成 NapCat 的前缀）

```
完整 UMO 形如：napcat-onebot:FriendMessage:你的QQ号
群：直接写群号
```

> 平台 ID 换了（`snowluma-onebot` → `napcat-onebot`），**UMO 前缀也必须跟着换**，否则白名单全部失效——这是迁移时最常见的坑。

### 5.3 语音 TTS

Linux 上没有桌面音频，但**语音合成不需要声卡**，只要能调 DashScope 就行。要注意：

```bash
ffmpeg -version     # 必须有，编解码/格式转换要用
```

AstrBot 的 TTS 配置里 `dual_output` 建议 **false**（只发语音不发文字）。

### 5.4 群聊唤醒

```json
"wake_prefix": ["/"]
```
@ / 引用也会唤醒，同上文。

## 6. 429 并发限制 → 排队代理（systemd 守护）

如果你的网关限制"非流式并发 = 2"，仍然需要这层代理（`tools/gw_proxy.py`）。

拷贝脚本：

```bash
mkdir -p /opt/astrbot/tools
# 从仓库把 tools/gw_proxy.py 传上去，例如：
# scp tools/gw_proxy.py root@你的IP:/opt/astrbot/tools/
chown -R astrbot:astrbot /opt/astrbot/tools
```

`/etc/systemd/system/gwproxy.service`：

```ini
[Unit]
Description=LLM Gateway Queue Proxy (8878)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=astrbot
WorkingDirectory=/opt/astrbot
# 上游网关地址：二选一（推荐写私有文件 /opt/astrbot/tools/gw.local.json）
Environment=GW_UPSTREAM=https://你的网关域名
ExecStart=/opt/astrbot/.venv/bin/python /opt/astrbot/tools/gw_proxy.py
Restart=always
RestartSec=3
StandardOutput=append:/opt/astrbot/logs/gwproxy.log
StandardError=append:/opt/astrbot/logs/gwproxy.log

[Install]
WantedBy=multi-user.target
```

> 也可以不写 `Environment`，改成建一个私有文件（不进仓库）：
> `echo '{"upstream":"https://你的网关域名"}' > /opt/astrbot/tools/gw.local.json`

```bash
mkdir -p /opt/astrbot/logs && chown astrbot:astrbot /opt/astrbot/logs
systemctl daemon-reload
systemctl enable --now gwproxy
curl http://127.0.0.1:8878/health
```

然后把模型 `base_url` 指到 `http://127.0.0.1:8878/v1`。


```bash
systemctl daemon-reload
```

## 8. 安全访问面板（别把 6185 暴露公网）

### 方案 A：SSH 隧道（推荐，零配置）

你自己的电脑上执行：

```bash
ssh -L 6185:127.0.0.1:6185 -L 6099:127.0.0.1:6099 root@你的IP -N
```

然后本地浏览器打开 <http://127.0.0.1:6185>（面板）、<http://127.0.0.1:6099>（NapCat）。

### 方案 B：nginx + 密码（有域名时）

```bash
apt install -y nginx apache2-utils
htpasswd -c /etc/nginx/.htpasswd admin
```

`/etc/nginx/sites-available/astrbot`：

```nginx
server {
    listen 80;
    server_name bot.example.com;

    location / {
        auth_basic "AstrBot";
        auth_basic_user_file /etc/nginx/.htpasswd;
        proxy_pass http://127.0.0.1:6185;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}
```

```bash
ln -s /etc/nginx/sites-available/astrbot /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

要 https 就用 `certbot --nginx -d bot.example.com`。

## 13. 云上常见故障

| 现象 | 原因 | 解决 |
|---|---|---|
| NapCat 连不上 AstrBot | 容器里 `127.0.0.1` 不是宿主机 | 用 `network_mode: host` 或 `ws://172.17.0.1:6199/ws` |
| 适配器一直不连 | AstrBot 只听 `127.0.0.1`，容器连不进来 | `ws_reverse_host` 改 `0.0.0.0` |
| 发消息没反应 | 白名单前缀还是 `snowluma-onebot` | 改成 `napcat-onebot:...` |
| 语音发不出/报 ffmpeg | 没装 ffmpeg | `apt install -y ffmpeg` |
| 面板打不开 | 6185 只监听本机 | 用 SSH 隧道（第 8 节） |
| 扫码一直失败 | 异地登录/IP 变化触发风控 | 换设备锁验证、稳定同一出口 IP、别频繁重启 |
| 内存吃满被 OOM | 上下文太长 + TTS | 加 swap、调小 `max_context_length`、限制并发 |
| 429 一堆 | 网关并发限制 | 上 `gwproxy`，base_url 指 `127.0.0.1:8878/v1` |
| 重启后 QQ 掉线 | 登录态目录没持久化 | 把 `/opt/napcat/qq` 挂宿主机卷 |

## 14. 附：一键安装脚本

`deploy/linux/install.sh`（配合本仓库使用）：

```bash
#!/usr/bin/env bash

APP_DIR=/opt/astrbot

```

```bash
chmod +x deploy/linux/install.sh && sudo ./deploy/linux/install.sh
```

## 15. 两台机器怎么选

| 场景 | 建议 |
|---|---|
| 就想自己玩、机器常开 | **Windows 本机方案**，装 SnowLuma 最快，还能扫码、能发语音 |
